## 一、现状分析

当前目录结构：

```
src/
├── App.tsx                    # 所有路由集中注册
├── components/
│   ├── orbital/               # 首页 3D 环绕文字（与业务无关）
│   ├── quiz/                  # ★ 混杂：通用题型 + LSAS 专属 + 报告
│   │   ├── types.ts           #   通用题型类型 + LSAS 类型混在一起
│   │   ├── OptionList.tsx / SingleChoice / MultipleChoice / Ordering   ← 通用可复用
│   │   ├── LsasQuestion.tsx / LsasReport.tsx / lsasReportConfig.ts     ← LSAS 专属
│   │   └── ScoreResult.tsx / index.ts
│   └── seo/
├── data/quizBank.ts           # ★ 同时承担通用题库 + LSAS 题库的加载
├── lib/scoring.ts             # 通用计分器
├── lib/scoring-lsas.ts        # LSAS 专属计分器（平级放在 lib，无归属）
├── routes/
│   ├── index.tsx              # 首页（只挂了「开始测试」一个入口）
│   ├── quiz.tsx               # ★ 列表页硬编码 Demo / LSAS 两张卡片
│   ├── quiz-demo.tsx          # ★ 路径命名混乱（不是心理学项目名）
│   └── lsas.tsx
public/
├── quiz-bank.json             # 前端综合测验数据
└── lsas.json                  # LSAS 量表数据
```

### 当前存在的问题

1. **缺少「测试项目」这一抽象**：新增一个测试项目时，需要改动 6~8 处（`quiz.tsx` 加卡片、`App.tsx` 加路由、`data/` 加加载函数、`lib/` 加计分器、`components/quiz/` 加组件、`routes/` 加页面），全是散点修改，极易漏改。
2. **领域归属混乱**：`scoring-lsas.ts`、`lsasReportConfig.ts`、`LsasQuestion.tsx` 都带 LSAS 前缀，却散落在 `lib/`、`components/quiz/` 中；通用题型组件与领域组件同目录混放。
3. **路径语义不清**：`/quiz-demo` 语义是"前端综合测验的 demo"，但后续测试项目都是心理学主题，该路径名无法复用。
4. **命名过窄**：`quiz`（小测）承载不了"量表"、"心理测验"等概念；`data/quizBank.ts` 同时管两类题库。
5. **一级模块缺失**：首页、导航没有为「心理游戏」「文章」预留扩展位。
6. **报告/计分无法随项目携带**：每个测试项目的报告配置、计分逻辑应跟随项目自包含，而不是散落全局。

## 二、目标架构总览

```
LOFN（心理学内容平台）
├── 测试题 Tests        ← 主模块，下面分多个测试项目
│   ├── 通用测验（前端综合 demo，示例项目）
│   └── LSAS 社交焦虑量表（已完成，作为第一个正式心理学项目）
│   └── …后续：MBTI / 焦虑自评 / 抑郁自评 …
├── 心理游戏 Games      ← 预留（先不做）
└── 文章 Articles       ← 预留（先不做）
```

每个测试项目自包含四样东西：**题库（数据）→ 答题组件（题型）→ 分数计算器 → 报告（组件+配置）**。

## 四、关键抽象：测试项目契约（Registry）

`features/tests/types.ts` 中定义统一契约，这是整个方案的核心：

```ts
interface TestProject {
  id: string                    // 'lsas' | 'quiz-demo' ...
  title: string                 // 展示名
  description: string
  badge?: string                // 卡片徽标文案（如「量表」「Demo」）
  loadBank: () => Promise<TestBank>          // 题库加载（类型化）
  components: QuestionComponentMap            // 题型组件映射（单题渲染）
  score: (bank, answers) => ScoreResult       // 计分器（通用 or 专属）
  Report: React.ComponentType<ReportProps>    // 报告组件（自带配置）
}
```

`registry.ts` 将各项目 `projects/*/index.ts` 聚合为一个数组：

```ts
export const TEST_PROJECTS: TestProject[] = [quizDemoProject, lsasProject]
export const getProject = (id: string) => TEST_PROJECTS.find(p => p.id === id)
```

**收益**：

- `TestListPage` 遍历 registry 渲染卡片 → 新增项目**不用再改列表页**；
- 作答容器 `TestRunnerPage` 通过 `useParams().id` 查 registry → **不用再改路由**；
- 项目自包含 → 删一个项目只需删一个目录。

> 说明：LSAS 是「双维等级量表」，与通用「单选/多选/排序」结构差异大，第一版作答容器允许项目级 `QuestionRenderer` 与 `score` 完全自定义（契约只约束输入/输出，不约束内部结构）。等后续项目增多、结构趋同后再进一步收敛容器。

## 五、路由规划

```
/                     首页（三模块入口卡片：测试题 / 心理游戏[敬请期待] / 文章[敬请期待]）
/tests                测试项目列表（registry 驱动）
/tests/:id            通用作答容器（由 registry 查找项目，渲染组件 + 计分 + 报告）
/games                心理游戏占位页（预留）
/articles             文章占位页（预留）
*                     → 404 重定向首页
```

相比现在：

| 现状 | 调整后 | 说明 |
|------|--------|------|
| `/quiz` | `/tests` | 一级模块语义 |
| `/quiz-demo` | `/tests/quiz-demo` | 成为某个项目的路径，不再占一级位置 |
| `/quiz/lsas` | `/tests/lsas` | 同上 |
| — | `/tests/:id` 动态路由 | 后续项目零路由改动 |

`App.tsx` 瘦身为纯路由表，`RootLayout` 可加一级导航（测试题 / 心理游戏 / 文章）。

## 六、数据层规划

- `public/*.json` 保留为题库静态数据（后续可无缝替换为 API）。
- 每个项目目录内的 `data.ts` 定义该项目题库的**类型**与**加载函数**（把现在 `data/quizBank.ts` 里的 `fetchLsasBank`/`fetchQuizBank` 分别下沉到对应项目）。
- `data/` 只留站点级配置（`site.ts`），`lib/scoring.ts` 保留通用计分器并归属 `features/tests/lib/`。

## 七、迁移步骤（建议顺序，本次不改动）

1. **建立骨架**：新增 `features/tests/`（registry、types、通用组件目录、lib、pages），`games`/`articles` 占位。
2. **下沉通用组件**：`components/quiz/` 中的 `OptionList`、`SingleChoice`、`MultipleChoice`、`Ordering`、`ScoreResult` 及 `types.ts` 迁入 `features/tests/components/`。
3. **项目化 LSAS**：将 `LsasQuestion`、`LsasReport`、`lsasReportConfig`、`scoring-lsas.ts`、`fetchLsasBank` 一并迁入 `projects/lsas/`，实现 `TestProject` 契约。
4. **项目化通用测验**：`quiz-demo` 注册为示例项目。
5. **改造页面**：`routes/quiz.tsx` → `pages/TestListPage`（registry 驱动）；`routes/lsas.tsx` + `routes/quiz-demo.tsx` → `pages/TestRunnerPage`（可先保留各项目页、后收敛）。
6. **调整路由**：按第五节映射更新 `App.tsx` 与导航。
7. **首页**：改为三模块入口。
8. **清理**：删除原 `routes/quiz-demo.tsx` 等迁移残留，跑通 `typecheck` / `build`。

## 八、后续新增一个心理学测试项目的标准流程

只需做一件事：在 `features/tests/projects/` 下新建一个目录并实现 `TestProject` 契约，然后到 `registry.ts` 注册一行。列表页、路由、作答容器自动生效。

新增项目清单（自包含四件套）：

- [ ] 题库数据：`public/<id>.json` + `data.ts`（类型 + 加载）
- [ ] 答题组件：项目专属题型组件（或复用通用组件）
- [ ] 分数计算器：`lib/scoring.ts`（或复用通用计分器）
- [ ] 报告：`report/` 下报告组件 + 配置
- [ ] `registry.ts` 注册一行

## 九、方案取舍说明

- **选择了「功能域 + 项目自包含」而非「纯按类型分层」**：因为测试项目之间差异主要在各项目内部（题型、计分、报告），自包含能最大化复用与解耦，避免散点修改。
- **未过度抽象作答容器**：LSAS 与通用测验结构差异大，第一版契约保留灵活性，避免强行统一导致复杂。
- **路径/命名一次改到位**：现在改 `/quiz` → `/tests` 成本最低，越晚改成本越高。
